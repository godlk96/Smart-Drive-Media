# 剪辑页片段剪辑与手柄调整工作流重构设计

- 日期：2026-10-14
- 项目：`smart-drive-media`（HarmonyOS ArkTS）
- 范围：`SegmentModel.ets` 片段算法、`CoreBridge.ets` 状态机、`SegmentTrack.ets` 轨道渲染与手柄拖拽手势、`SegmentParamRow.ets` 参数行、`Editor.ets` 交互联动

---

## 1. 背景与意图（Why）

当前剪辑页的多片段系统采用的是“落刀裁切 + 置灰停用（软删除）”机制。用户在实际使用中存在强烈的操作诉求与心智断层：
1. **原片默认可用**：进页面时用户往往只想调个倍速或静音就直接导出，并不想强制剪辑；
2. **直觉的高光提取**：点击剪辑时，用户希望在当前播放头处快速圈出一块区域，并通过两端手柄自由缩放；
3. **物理删除与干净重置**：不需要复杂的“置灰再恢复”状态机，点删除就彻底移走该片段；若片段全删光，自然回到未剪辑的原始全片状态。

## 2. 目标、非目标与反目标

### 2.1 目标（Goals）
1. **全片原始状态**：进入剪辑页默认覆盖全片（`0 ~ totalDurationSec`），不显示片段手柄；用户可直接调整全片倍速、声音，并直接导出 60 秒完整成片。
2. **首次剪辑高光提取**：在原始状态下点击剪辑按钮，在播放头所在位置生成一个默认长度为 15 秒的标准高光选区（若剩余不足 15 秒则到片尾，且保证 $\ge 10$ 秒），进入多片段编辑模式。
3. **双向手柄拉伸与碰撞阻挡**：
   - 只有当前被选中的片段才展示左右两侧拖动手柄。
   - 左右手柄均支持拖动调整起始点和终止点。
   - **硬阻挡（Clamp）**：手柄拖动碰到片头（0s）、片尾或相邻片段边界时直接顶住，绝对不推移、不压缩其他片段，绝不允许重叠。
   - **最小段长约束**：单段最短 **10 秒**（`MIN_SEGMENT_SEC = 10`），两端手柄向内收缩到 10 秒时硬顶住，禁止拉反。
4. **后续落刀规则**：
   - **片段内切分（一分为二）**：仅当片段时长 $\ge 20$ 秒，且落刀点距离两端均 $\ge 10$ 秒时允许落刀切分成两段；否则剪辑按钮置灰。
   - **空档内添加**：在两段之间的空档（或最后一段之后）点击剪辑，生成一个起始于当前播放头、默认长 15 秒（遇后段边界阻挡则截断，且必须 $\ge 10$ 秒）的新片段。
   - **上限限制**：最多支持 **3 个片段**（`MAX_SEGMENTS = 3`），满 3 段后剪辑按钮置灰。
5. **直接物理删除（无置灰）**：
   - 点击参数行【✕】按钮直接从数组中物理移除当前选中的片段，UI 轨道上该块直接消失。
   - 若还有其他片段，焦点顺延到下一个相邻片段。
   - **删光重置**：若所有片段都被删光，系统无缝重置回“全片原始状态”（覆盖全片，可调速/静音，可直接导出）。

### 2.2 非目标（Non-Goals）
- 不动底层硬件导出的原生服务（FFmpeg/AVPlayer 原生能力）。
- 不动多机位模板分屏排布规则（5 种 TemplateCard 保持原逻辑）。

### 2.3 反目标（Anti-Goals）
- 严禁“推移挤压相邻片段”：绝不让前一个片段的拉长暗中修改后一个片段已调好的起始时间。
- 严禁“落刀默认延伸到片尾”：绝不强制生成几十秒的超长段落逼迫用户每次长途拖拉右手柄。
- 严禁“删光后禁用导出/空界面挂起”：绝不让用户在删掉所有片段后陷入无法导出或界面空白的状态。

## 3. 核心交互与状态机规格

### 3.1 页面模式定义

系统在两个主模式之间平滑切换：
- **`RAW_FULL`（全片模式）**：
  - `segments` 表现为单一虚拟全片 `[0, totalDurationSec]`。
  - 参数行显示：`全片` · `60s` · 倍速微胶囊 · 声音微胶囊 · 剪辑图标。
  - **无【✕】删除按钮**（全片无法被删除）。
  - 轨道显示为平铺通长条，无两侧拉动手柄。
  - 右上角【导出】高亮可用，导出时长为全片时长。
- **`SEGMENTED`（多片段模式）**：
  - 存在 1~3 个独立片段。
  - **在片段内时**（`selectedSegmentId >= 0`）：
    - 选中的片段具有 1.5vp 琥珀边框和左右两侧调节手柄。
    - 参数行显示：`片段 N` · 时长 · 倍速胶囊 · 声音图标 · 剪刀 · `✕`。
  - **在空白区间（Gap）时**（`selectedSegmentId == -1`）：
    - 当播放头拖动或停留在片段之外的空白区域时，自动进入空白区间状态。
    - 轨道上所有片段取消边框与手柄。
    - 参数行显示：`空白区间`，**隐藏倍速胶囊、声音图标与【✕】删除按钮，仅保留剪刀按钮**（点击即可在当前落刀插入新片段）。
    - 用户若在轨道上手动点击某个片段，立即恢复该片段的选中编辑态。

### 3.2 首次剪辑（`RAW_FULL` $\rightarrow$ `SEGMENTED`）
- 触发条件：在 `RAW_FULL` 状态下，用户点击参数行剪刀（`66095d8` 已把剪辑按钮从画面浮层移到参数行右侧）。
- 设播放头位置为 $t$，源片总长 $T$：
  - 若 $T - t < 10$，提示“距离片尾不足10秒，无法截取”，拦截操作。
  - 新片段起点 $start = t$。
  - 新片段终点 $end = \min(T, t + 15)$。
  - 构造 `Segment { id: 0, startSec: start, endSec: end, speedLabel: 原全片倍速, muted: 原全片静音 }`。
  - 切换到 `SEGMENTED` 模式，选中该唯一片段。

### 3.3 轨道手柄拖拽（Drag Handles）
- 选中的片段两端各有一个竖向琥珀拉动手柄（左手柄 `handleLeft`，右手柄 `handleRight`）。
- **拖动左手柄（改变起点 $S$）**：
  - 向左移动最小值：左侧相邻片段的 `endSec`（若左边无片段则为 0）。
  - 向右移动最大值：当前片段的 $E - 10$（保证单段至少 10 秒）。
  - 满足 $S_{new} = \text{clamp}(x, S_{min}, S_{max})$。
- **拖动右手柄（改变终点 $E$）**：
  - 向左移动最小值：当前片段的 $S + 10$（保证单段至少 10 秒）。
  - 向右移动最大值：右侧相邻片段的 `startSec`（若右边无片段则为 $T$）。
  - 满足 $E_{new} = \text{clamp}(x, E_{min}, E_{max})$。
- 拖动时，手柄上方展示浮动气泡显示当前调整的秒数（如 `0:24`），松手气泡消失。

### 3.4 后续剪刀落刀（`SEGMENTED` 模式）
在时间点 $t$ 点击剪刀：
1. **若当前有效片段数已满 3 个**：提示“最多只能添加3个剪辑点”，拦截。
2. **落刀点在某个片段内部 `[start, end]`**：
   - 校验：必须满足 $t - start \ge 10$ 且 $end - t \ge 10$（片段长度必须 $\ge 20$s）。
   - 若不满足：提示“片段至少需20秒才可切分”，拦截。
   - 若满足：原片段分裂为 `[start, t]` 和 `[t, end]`，后半段赋予新 ID，自动选中后半段。
3. **落刀点在空白区间（两段之间或最后一段之后）**：
   - 寻找 $t$ 之后的下一个片段起点 $nextStart$（若后方无片段则为 $T$）。
   - 校验：若 $nextStart - t < 10$，提示“剩余空间不足10秒”，拦截。
   - 若满足：插入新片段 $[t, \min(nextStart, t + 15)]$，自动选中新片段。

### 3.5 删除操作（【✕】微胶囊）
- 在 `SEGMENTED` 模式下，参数行提供【✕】按钮。
- 点击【✕】：
  - 从 `state.segments` 物理移除目标片段（`splice`）。
  - **播放头保持不变**：播放头位置（`playheadSec`）完全不跳跃，保留在原秒数。
  - 若剩余片段数 $> 0$：
    - 优先将焦点顺延至原片段右侧的第一个片段；若右侧无片段，则顺延至左侧最后一个片段。
    - 若此时播放头恰好在新片段内，则呈现新片段选中态；若此时播放头停留在空白处，则自动呈现“空白区间”态。
  - 若剩余片段数 $== 0$：
    - 状态立即恢复为 `RAW_FULL` 模式（创建 `createFullSegment(T)`）。
    - 界面提示 Toast：“已恢复为完整视频”。

### 3.6 关键实现约定（构建者决策 / Builder's Calls）
1. **手柄拖拽与预览寻道（Seek）性能管线**：
   - 手柄拖动时，时间气泡 60Hz 实时响应手势；
   - 画面寻道（`requestPreviewSeek`）采用 **80ms 节流（Throttle）** 发送，松手（`PanGesture.onActionEnd`）时补发一次最终精准寻道。既保证多机位原生解码器不丢帧紊乱，又实现所见即所得。
2. **空档插入新片段初始参数**：
   - 在空白区间落刀创建新片段时，倍速默认设为 `1.0X`，声音默认设为未静音（原声），保持纯净初始状态。
3. **删光恢复全片属性**：
   - 全部删光重置为 `RAW_FULL` 时，全片倍速与静音重置为 `1.0X` / 原声。
4. **轨道布局不变量（`buildTimelineItems` + `widthForSec`）**：
   - **空白区恒建**：片头、每两段之间、片尾的空白区项**必须始终存在于 `buildTimelineItems()` 的返回数组里**，时长为 0 时也照样建（绝对宽度就是 0vp，视觉上不可见）。
   - 原因：这些项是拖动时“让出/顶开”的那几秒的唯一容器。若只在时长 > 0 时才建，两段紧贴（如 15-30 与 30-45）时中间没有空档项，把前一段段尾往左拖，让出的 5 秒无处安放，整条轨道的宽度分配就少了一截，**后面那个片段也跟着位移、宽度也变**；松手提交后结构里终于有了真空档，画面又弹回原位。这就是“拖动时后段跟着动、松手回弹”的根因。
   - 推论（新增空白区必须已有容器）：拖第一段左手柄会在片头撑开新空档，拖最后一段右手柄会在片尾撑开新空档，同理都必须预先建项。
   - 键名必须**同时**带上「相邻段 id」和「这一项自己的已提交边界秒数」（`gap-head-${id}-0-${startSec}` / `gap-${leftId}-${rightId}-${leftEndSec}-${rightStartSec}` / `gap-tail-${id}-${endSec}-${totalDurationSec}`），恒建的项数固定为 `2N+1`。
   - 为什么不能只用 id：空档的宽度不是由它自己的 item 决定的，而是 `liveGapWeight(item)` 拿**建项时捕获的** `startSec`/`endSec` 去和“正在被拖的那条边界”比对现算的，而 ForEach 按 key 复用子组件时**不会重跑 item 生成函数**。只用 id 时，松手提交后新项的 key 与旧项完全相同 → 子组件被原样复用、手里还是上一轮的旧边界 → 新旧边界对不上，两侧“贴着被拖边界”的判断全部落空，空档宽度退回旧值 0，紧贴的那一段被画到错误位置（表现为：第一次拖动还跟手，松手后紧贴的那段跳到错误位置，从第二次拖动起空档再也不跟手、后段跟着前段的边一起滑）。带上已提交边界后，拖动期间提交值不变 → key 稳定、子组件照旧复用（这正是本节要的“拖动期间结构不变”）；松手提交后边界变了 → key 变、子组件重建，拿到的是刚生成的新项。段块的 `blockKey` 本来就把边界编进 key，空档此前漏了。
   - **手柄触摸区不得越界**：两个手柄必须各自锚在自己的那条边上（各自的 Stack 自己 `alignContent`），触摸区宽度按块宽现算（`handleTouchWidth`）且完全落在段块内，**禁止再用 `Row(){ 左手柄; Blank(); 右手柄 }` 流式排版**。
   - 原因：手柄是固定 44vp 宽。块宽 < 88vp 时 Row 放不下 —— 左手柄占满整块、`Blank()` 被压到 0、右手柄被排到块内固定的 `x=44..88vp` 处，再叠加它自己的 `+22` 居中偏移，圆点就落在**块内固定 x≈88vp** 上：块越窄离真正的右边界越远（60s 片长里一个 15s 段只有 68.5vp 宽，圆点已经跑到块外；最后一段后面是透明的片尾空档，所以整颗圆点都看得见），点它也抓不到真正的右边界。圆点视觉上仍画在边界上，但它单独成层且 `HitTestMode.None`：伸到相邻段上的那半截不吃触摸，点在相邻段上仍然选中相邻段（旧写法左右各摊 22vp，会盖住相邻段，相邻段比 22vp 窄时整块都点不中）。
   - **宽度绝对化**：段块与空白区块一律用 `.width(this.widthForSec(时长))`（= 轨宽 × 时长 / 片长），**禁止用 `layoutWeight`**。
   - 原因：`layoutWeight` 是按权重比例分摊整条轨道（每项实得 = 轨宽 × w_i / Σw）。只要有一项的值不对或某一帧没刷新，整行都会按比例重摊一遍，旁边的段跟着被拉伸或压缩 —— 这正是“拖这一段，另一段被压扁/拉长”的来源。绝对宽度下每一项只由自己的时长决定，互不牵连。
   - 不变量：**所有项的时长之和恒等于片长**（恒建空白区保证），于是各绝对宽度之和恰好等于轨宽，轨道被精确铺满且每一项的位置只由它前面各项的时长决定。
   - 以上四条不变量由 `tools/offline-test.mjs` 的 `checkGapItemsAlwaysBuilt`、`checkTrackUsesAbsoluteWidths`、`checkGapKeysCarryCommittedBounds` 与 `checkHandleTouchAreasStayInsideBlock` 守卫钉死。

## 4. 架构与模块改动清单

### 4.1 模型层 `SegmentModel.ets`
- 常量调整：`MIN_SEGMENT_SEC = 10`，新增 `DEFAULT_WINDOW_SEC = 15`。
- 新增/调整纯函数：
  - `adjustSegmentStart(segments, id, targetSec): Array<Segment>`
  - `adjustSegmentEnd(segments, id, targetSec): Array<Segment>`
  - `removeSegment(segments, id): Array<Segment>`
  - `canSplitOrInsertAt(segments, sec, totalDurationSec, isRawFull): boolean`
  - `splitOrInsertAt(segments, sec, totalDurationSec, isRawFull): Array<Segment>`
- 保持纯函数无 `@ohos.*` 依赖，可通过独立测试脚本做 100% 断言验证。

### 4.2 桥接层与状态机 `CoreBridge.ets` & `EditorViewModel.ets`
- 维护 `isRawFull: boolean` 状态标志。
- 适配 `deleteSegment(id)`：执行物理移除，当数组为空时切换为全片并保留用户当前设置的倍速/静音。
- 暴露 `adjustSegmentBoundaries` 接口供手势更新。

### 4.3 视图层 `SegmentTrack.ets` & `SegmentParamRow.ets`
- `SegmentTrack.ets`：
  - 仅给 `isSelected` 的片段渲染左右两个 Handle。
  - 给 Handle 绑定 `GestureGroup(GestureMode.Exclusive, PanGesture(...))` 手势，支持水平拖拽，实时上报 `onAdjustStart` / `onAdjustEnd`。
- `SegmentParamRow.ets`：
  - 区分 `isRawFull` 状态：全片状态下隐藏【✕】微胶囊，文案为“全片 · 时长”；多片段状态下文案为“片段 N · 时长”，展示【✕】微胶囊。
