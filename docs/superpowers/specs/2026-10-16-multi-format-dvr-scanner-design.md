## 1. 目标与背景 (Intent & The Why)

### 1.1 现状与痛点
目前 `Smart-Drive-Media`（鸿蒙智能行车视频编辑与多视角合成工具）仅硬编码支持**华为 ADS** 的循环录像与哨兵视频文件命名格式：
- `DVR_LoopRecording_YYYY-MM-DD_HH-mm-ss_camera.mp4`
- `Sentry_YYYY-MM-DD_HH-mm-ss_camera.mp4`

然而在实际车主使用场景中：
1. **车型与品牌繁多**：特斯拉（Tesla 四机位独立文件）、比亚迪（BYD）、理想、蔚来、小米汽车，以及盯盯拍、70迈、海康威视等第三方独立后装记录仪，其命名规则各不相同。
2. **车企 OTA 变更频繁**：车机系统更新常常改动前缀、分隔符或机位代号。硬编码的静态匹配极易在新版 OTA 后失效。
3. **用户门槛问题**：普通车主完全不懂正则表达式，无法要求用户输入正则来适配自己的汽车。

### 1.2 核心目标
构建一套**“预设精准规则 + 占位符自定义 + 智能启发式兜底”**的分层 DVR 文件名解析与识别体系。用户不仅可以一键选择主流车型，还可以通过简单的语义占位符添加自定义规则；当规则未命中或遇 OTA 变化时，由“智能兼容兜底引擎”自动提取时间与机位，确保多路及单路视频均可无感导入并生成时间线。

## 2. 目标、非目标与反目标 (Goals, Non-Goals & Anti-Goals)

### 2.1 目标 (Goals)
1. **多品牌开箱即用**：内置主流车系预设规则（华为 ADS、特斯拉、比亚迪、通用单摄等）。
2. **零代码占位符自定义**：提供直观的语义占位符（如 `{YYYY}-{MM}-{DD}_{HH}-{mm}-{ss}_{CAMERA}`），由系统自动编译为正则，彻底屏蔽正则语法。
3. **智能启发式兜底（带独立开关）**：提供“智能兼容模式”开关，开启后对未命中规则的文件进行通用时间与机位语义嗅探。
4. **两大致命边界容错**：
   - **时间降级**：仅有分钟时自动补零；纯流水号无时间时降级使用媒体库底层录制/入库时间（`date_added`）。
   - **单摄机位兜底**：完全无机位标识的单路视频，自动归派为 `Front`（主前视）并匹配单视角模板 `T5`。
5. **防相册误报机制**：设计相册范围隔离与特征置信度，严防日常非车载视频被误识别。

### 2.2 非目标 (Non-Goals)
- 本期不引入云端动态下发规则服务，保持端侧纯净离线运行能力，所有配置持久化在本地 `PreferencesService`。
- 不负责修复损坏、丢帧或无法解码的视频物理文件。

### 2.3 反目标 (Anti-Goals - 做了就算失败)
- **严禁向普通用户暴露正则表达式**输入框或调试界面。
- **严禁过度放宽启发式导致图库污染**：绝不能把相册里的拍娃、旅游生活视频误当成行车记录仪切片批量导入行程列表。

## 4. 详细模块设计与规范

### 4.1 数据契约与实体定义
保持下游完全无感，继续输出标准的 `DvrMeta` 结构：
```typescript
export class DvrMeta {
  fileName: string = ''
  uri: string = ''
  date: string = ''        // YYYY-MM-DD
  time: string = ''        // HH:mm:ss
  camera: string = ''      // Front | Back | Left | Right | LeftFront | RightFront
  timestamp: number = 0    // 毫秒时间戳
}
```

### 4.2 语义占位符系统 (Visual Placeholder System)
针对不愿写正则的用户，规则仅由**文件名模板**与**机位别名映射**组成：

1. **支持的占位符列表**：
   - `{YYYY}`：4 位年份数字（如 2024）
   - `{MM}`：2 位月份（01~12）
   - `{DD}`：2 位日期（01~31）
   - `{HH}`：2 位小时（00~23）
   - `{mm}`：2 位分钟（00~59）
   - `{ss}`：2 位秒（00~59）
   - `{CAMERA}`：机位代号文本（如 front, rear, f, b, cam1 等）
   - `{EVENT}`（可选）：录像事件类型（loop, sentry, emg）
   - `*`：任意通配符（转义为 `.*?`）

2. **自动编译逻辑 (`compileTemplateToRegex`)**：
   - 将文本中的特殊字符（`.`, `+`, `_`, `-`, `(` 等）转义；
   - 将 `{YYYY}` 替换为 `(?<year>\\d{4})`；
   - 将 `{MM}`, `{DD}`, `{HH}`, `{mm}`, `{ss}` 分别替换为带具名捕获组的 2 位数字；
   - 将 `{CAMERA}` 替换为 `(?<camera>[a-zA-Z0-9_-]+)`；
   - 生成标准的 ECMAScript 正则表达式，并自动添加文件后缀支持 `\\.(mp4|mov|ts)$`。

3. **机位别名归一化对照表**：
   每个预设包含一份简单的映射字典：
   ```json
   {
     "Front": ["front", "ft", "f", "forward", "cam1", "前"],
     "Back": ["back", "rear", "rr", "b", "cam2", "后"],
     "Left": ["left", "lt", "l", "left_repeater", "cam3", "左"],
     "Right": ["right", "rt", "r", "right_repeater", "cam4", "右"],
     "LeftFront": ["left_front", "lf"],
     "RightFront": ["right_front", "rf"]
   }
   ```

### 4.3 启发式扫描引擎与漏洞防线 (Heuristics & Safe Fallback)

针对车企 OTA 变更、未收录车型以及用户指出的**两大致命漏洞**，实现以下多级防御：

#### 防线 A：时间提取与精度降级
1. **多格式正则嗅探**：尝试匹配文件名中的连续时间特征：
   - 模式 1：`202[0-9][-._]?(0[1-9]|1[0-2])[-._]?(0[1-9]|[12]\d|3[01])[-._]?(0\d|1\d|2[0-3])[-._]?([0-5]\d)[-._]?([0-5]\d)`（完整的年月日时分秒）
   - 模式 2：`202[0-9][-._]?(0[1-9]|1[0-2])[-._]?(0[1-9]|[12]\d|3[01])[-._]?(0\d|1\d|2[0-3])[-._]?([0-5]\d)`（仅精确到分）
2. **秒级时间缺失处理**：
   - 若命中模式 2（仅到分钟），秒自动补齐为 `00`（即 `HH:mm:00`）。
3. **底层元数据兜底 (Metadata Fallback)**：
   - 若文件名属于纯序号（如 `FILE0001.mp4`、`DCIM_0088.mp4`）导致文件名完全无时间：
   - 直接读取系统的 `PhotoAsset.date_added`（或 `date_modified`）作为拍摄基准时间，格式化为 `date` 与 `time`。

#### 防线 B：单摄与未知机位兜底
1. **机位关键词探测**：在文件名中搜索内置的全局机位字典（中英文）。
2. **单摄无机位时的默认指派**：
   - 若文件名完全未发现机位关键词，**默认认定为 `Front`（前摄）**。
   - 下游时间线构建自动将其纳入单轨道，并在编辑页自动适配 `T5（单视角）` 模板。

#### 防线 C：相册范围与误识别安全锁（防止污染正常相册）
全相册扫描下，若单摄无机位规则过于宽松，会导致手机拍摄的普通视频被误当做行车记录仪。因此在启发式模式下启用**“双保险安全锁”**：
1. **相册优先与隔离**：
   - 默认仅在指定的“车载相册”中启用启发式深度嗅探（包括系统的 `Huawei Share` 华为分享相册、名称包含 `DVR` / `Dashcam` / `行车记录仪` 的用户相册）。
2. **切片特征置信度校验**：
   - 若用户选择在全图库扫描，一个视频要被判定为启发式 DVR 视频，必须满足以下两项之一：
     - a. 命中明确的机位词（如 front/rear/cam）；
     - b. 具有行车记录仪切片特征（同一相册下存在连续的两个以上时长在 1~5 分钟内等长分段视频，或包含常见前缀如 `REC_`, `DVR_`, `NO_`, `Sentry_`）。

## 5. 评审问题裁决与工程收敛 (Builder Check Decisions)

在工程预审中，针对多格式扩展与现有代码库的边界冲突，作出以下明确裁定：

### 5.1 已确认为工程默认决策 (Our Call)
1. **Tier 1 规则执行策略：全量预设瀑布流自动匹配 (Auto-Waterfall)**
   - 扫描时自动依次尝试：`用户自定义规则` -> `华为 ADS` -> `特斯拉` -> `通用单摄`。
   - 用户无需每次进入设置页手动切换车型；设置页仅供用户开启/关闭“智能兜底”或输入自定义占位符。
2. **相册扫描范围策略：沿用现有自动降级阶梯**
   - 优先扫描 `Huawei Share` 等专用车载相册；若为空则自动降级为全图库扫描。暂不增加相册选择 UI，避免增加用户认知负担。
3. **接口扩展平滑度**：
   - 将 `parseDvrFileName(name: string, uri: string)` 扩充为可选入参 `parseDvrFileName(name: string, uri: string, dateAddedSec?: number)`。
   - 当文件名仅精确到分或无秒时，若有 `dateAddedSec` 则作为微秒级对齐依据，无需推翻现有单文件扫描流水线。
4. **防线 C2 判定简化**：
   - 废弃复杂的跨文件等长统计；改用轻量级指纹规则（合法时间戳 + 常见车载前缀 `REC_` / `DVR_` / `VID_` / `NO_` 等），毫秒级判定。

### 5.2 待用户确认的关键决策 (Pending User Decision)
- **切片时长（60秒 vs 动态 1~5分钟）**：
  - 现有播放器与行程构建深度绑定了 60 秒切片（华为 ADS 与特斯拉出厂均为 60 秒单切片）。
  - 若引入 3 分钟/5 分钟的第三方记录仪切片，第一期建议在行程聚合层支持动态 duration 拼接，暂不打破 60s 细粒度网格；若需彻底改造底层网格，工作量将大幅扩张。

## 6. 用户交互与配置管理

### 6.1 设置项定义
持久化在 `PreferencesService` 中：
- `heuristicFallbackEnabled: boolean`：智能兼容兜底开关（默认 `true`，防止 OTA 漏抓）
- `customPlaceholderTemplate: string`：用户自定义占位符模板
- `customCameraMapping: string`（JSON 字符串）：用户自定义的机位对照字典

### 6.2 极简 UI 设计（设置弹窗/页面）
1. **智能兼容模式（开关）**：附带清晰说明文字：“当记录仪更新导致规则未命中时，自动通过智能算法提取时间与视角”。
2. **自定义规则展开面板**：
   - 文本输入框：带胶囊标签一键插入 `{YYYY}`, `{MM}`, `{DD}`, `{HH}`, `{mm}`, `{ss}`, `{CAMERA}`；
   - 实时预览提示：“根据您当前输入的格式，将匹配形如 `REC_20241015_123000_front.mp4` 的文件”。
