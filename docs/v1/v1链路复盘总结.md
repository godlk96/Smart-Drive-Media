# 导出链路复盘总结

## 一、实现了哪些功能

### 1. 导出主链路能力落地

- 实现“前后分轨时间拼接 + 上下合成”导出策略。
- 导出管线版本标记为 `native-stack-v6`，便于日志追踪。
- 导出完成后自动写入系统相册并回传相册 URI。

### 2. FFmpeg 能力接入

- 从自定义本地 SDK 方案切换到 `@sj/ffmpeg` 依赖方案。
- 在 ArkTS 中直接调用 `FFmpeg.execute(...)` 实现合成。
- 依赖固定为 `@sj/ffmpeg: 2.0.2`，降低“latest 漂移风险”。

### 3. 全链路可观测性

- 增加导出策略、输入统计、失败原因、写入结果等关键日志。
- 增加导出成功日志：合成完成、写入相册完成、任务完成。

## 二、修复了哪些 BUG

### 1. 构建与编译问题

- 修复 ArkTS `throw` 限制引发的编译失败（抛任意类型导致失败）。
- 修复环境配置导致的 hvigor 同步失败（`DEVECO_SDK_HOME` 无效）。

### 2. 导出执行问题

- 修复 `No such file or directory`：增加输入可读性探测与文件 staged copy。
- 修复 `Option not found`：增加 FFmpeg 参数兼容降级重试逻辑。
- 修复执行卡住无感知：加入超时中断与进度日志机制。

### 3. 运行稳定性问题

- 修复导出回调与执行阶段不稳定问题，收敛执行参数与错误透出。
- 移除 CMake 对预置 FFmpeg SDK 文件的强依赖告警路径，避免误导。

## 三、遇到的问题与解决过程

### 1. 本地 SDK 文件获取困难

- 问题：`libsmartdrive_ffmpeg_sdk.so` 来源不稳定，阻塞开发。
- 解决：改为直接使用 ohpm 依赖 `@sj/ffmpeg`，摆脱手工分发 so 的瓶颈。

### 2. 不同设备参数兼容性差异

- 问题：部分参数在目标设备上触发 `Option not found`。
- 解决：主命令失败后自动切换最小参数重试，提高真机通过率。

### 3. 素材路径可访问性差异

- 问题：媒体 URI 在 FFmpeg 执行上下文中不可读。
- 解决：先校验可读性，不可直读则复制到应用 cache 后再输入 FFmpeg。

### 4. 导出耗时与卡住感知

- 问题：长时任务用户感知差，失败原因不清晰。
- 解决：增加进度日志、超时中断和统一错误映射。

## 四、新增功能

### 1. 目标码率贴近源视频

- 新增 ffprobe 读取输入视频码率能力。
- 导出时按前后输入码率估算目标码率，动态设置 `b:v/maxrate/bufsize`。
- 目标是减少不必要压缩，让输出体积和质量更接近源素材。

### 2. 执行韧性增强

- 新增“参数不兼容自动降级”机制。
- 新增可控超时取消，避免无限等待。

## 五、当前风险

### 1. 许可证风险

- `@sj/ffmpeg` 为 GPL 体系，发布前需进行法务合规评估。

### 2. 设备差异风险

- 不同机型/系统镜像的 ffmpeg 功能集差异较大，参数兼容仍有长尾。

### 3. 性能与功耗风险

- 上下合成属于重编码场景，长视频在中低端设备上可能出现高耗时和高温。

### 4. “完全不压缩”边界

- 当前是 filter_complex 合成路径，技术上无法无损 `-c copy` 直出，只能“尽量接近源质量/体积”。

## 六、未来规划建议

### 1. 短期（稳定性）

- 建立机型参数白名单（线程、码率上限、分辨率上限）。
- 细化错误码分类，前端给出可操作的用户提示。

### 2. 中期（体验）

- 增强导出进度展示（解析 FFmpeg 进度消息并映射 UI 百分比）。
- 提供“高质量 / 快速导出”双模式切换。

### 3. 长期（工程化）

- 抽象统一转码适配层，降低对单一三方包 API 细节的耦合。
- 建立真机回归矩阵与日志基线，形成稳定的发布前验证流程。

## 七、当前结果状态

- 已在真机日志确认完整成功链路：
  - FFmpeg 合成完成
  - 写入相册完成
  - 导出任务完成（含相册 URI）
- 当前版本可满足“导出到相册”的核心业务目标。
